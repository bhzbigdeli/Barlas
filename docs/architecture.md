# معماری برلاس

## لایه‌ها

```
Api  →  Infrastructure  →  Application  →  Domain
```

- **Domain**: موجودیت‌ها با قواعد داخلی‌شان. هیچ وابستگی بیرونی ندارد. خطای قاعده = `DomainException` (پیام فارسی، HTTP 422).
- **Application**: سرویس‌ها روی `IAppDbContext` (همان DbSetهای EF؛ ریپازیتوری جدا نداریم). خطای قابل‌انتظار = `AppException`.
- **Infrastructure**: `AppDbContext`، پیکربندی جدول‌ها، migration، `ExcelOrderSource`، `DbSeeder`.
- **Api**: کنترلرهای نازک، JWT، سیاست‌های نقش، `ErrorHandler` → ProblemDetails.

## نگاشت سند طرح کلی به کد

| مفهوم در سند | کد |
|---|---|
| واحد (واحد اصلی، سالن صندل) | `ProductionUnit` — `SupplierCode` = کد تامین‌کننده در سیستم فروش تهران |
| اطلاعات پایه مشترک | `ShoeModel` (محصول) با سری خودش `SeriesSize`، `Color`، `Sole` (زیره)، `ProductionRoute`/`ProductionStage` (مسیر مراحل)، `PieceRate` (نرخ دستمزد) |
| سری سایز | هر محصول بازه و ترکیب خودش را دارد (مثلاً ۳۷ تا ۴۲، یا ۴۰ تا ۴۵ با دو جفت ۴۱). `ShoeModel.Expand(n)` = جفت هر سایز برای n سری |
| سفارش تهران | `SalesOrder` → `SalesOrderLine` (مدل+رنگ) → `SalesOrderLineSize` (تعداد هر سایز، سهم موجودی آزاد، سهم تولید) |
| موجودی آزاد انبار | `FreeStockItem` (واحد+مدل+رنگ+سایز) و سابقه `StockMovement` |
| سنجش با موجودی آزاد | `FreeStockAllocator.Allocate` — هنگام دریافت سفارش اجرا می‌شود |
| زیربرنامه | `ProductionPlan` + `PlanLine` (سهم سفارش + مازاد). `Submit` اگر مازاد > آستانه واحد (۲۰٪) باشد → `AwaitingApproval` |
| دسته و کاردکس QR | `Bundle` با `QrToken` تصادفی، جدول سایز، و کپی مسیر مراحل در لحظه صدور |
| اسکن مراحل با گوشی | `Bundle.CompleteStage` / `SendBackForRework` → `StageScan` (کارکرد هر کارگر؛ پایه دستمزد فاز ۲) |
| ورود به انبار، مازاد | `WarehouseReceipt.Receive` — اول سهم سفارش، بقیه به موجودی آزاد |

## کاربران و سطوح دسترسی

- **مجوزها** (`Permission`) در کد ثابت‌اند: دیدن همه واحدها، تعریف کاربران و سطوح، تعریف محصول، ورود سفارش،
  برنامه‌ریزی، تأیید مازاد، اسکن مراحل، انبار، گزارش‌ها. نام فارسی‌شان در `PermissionCatalog`.
- **سطح دسترسی** (`Role`) در برنامه تعریف می‌شود: نام + مجموعه مجوزها. سطح «مالک» سیستمی است، همه مجوزها را دارد
  و قابل حذف/تغییر مجوز نیست. سطوح پیش‌فرض فقط بار اول ساخته می‌شوند.
- **کاربر** یک سطح دارد و اگر سطحش «دیدن همه واحدها» نداشته باشد باید یک واحد داشته باشد.
  حداقل یک مالک فعال همیشه می‌ماند؛ کسی خودش را غیرفعال نمی‌کند. رمز: حداقل ۸ کاراکتر با حرف و عدد.
- **اعمال**: توکن JWT فقط شناسه کاربر را دارد. `LoadCurrentUserMiddleware` در هر درخواست کاربر و سطحش را از
  دیتابیس می‌خواند، پس غیرفعال‌کردن کاربر یا تغییر مجوزها فوراً اثر دارد. هر مجوز یک policy هم‌نام دارد:
  `[Authorize(Policy = nameof(Permission.ManageUsers))]`.
- **هر واحد فقط داده خودش**: هر موجودیتی که `IUnitScoped` است فیلتر سراسری EF دارد
  (`SeesAllUnits || UnitId == واحد کاربر`). کار سیستمی بیرون از درخواست HTTP (seed) همه را می‌بیند. جایی که عمداً
  باید از فیلتر عبور کرد (دریافت سفارش برای همه واحدها) `IgnoreQueryFilters()` صریح نوشته شده.
- اطلاعات پایه را همه می‌بینند؛ نوشتن فقط با مجوز «تعریف محصول».

## دریافت سفارش از تهران

روش اتصال هنوز قطعی نیست. رابط `IOrderSource` منبع را جدا می‌کند:

- **فعلاً**: `ExcelOrderSource` — قالب موقت، هر ردیف یک سایز:
  `کد تامین‌کننده | شماره سفارش | تاریخ سفارش | تاریخ تحویل | مشتری | کد مدل | کد رنگ | سایز | تعداد`
  (تاریخ شمسی یا میلادی، ارقام فارسی قابل قبول). اگر «سایز» خالی باشد، «تعداد» = تعداد سری و طبق سری همان محصول باز می‌شود.
- **بعداً**: پیاده‌سازی API همین رابط را پیاده می‌کند و یک کار زمان‌بندی‌شده `OrderIntakeService` را صدا می‌زند.

ورود دوباره همان سفارش (همان شماره در همان واحد) نادیده گرفته می‌شود.

## هم‌زمانی

`FreeStockItem` و `Bundle` ستون `RowVersion` دارند؛ دو رزرو یا دو اسکن هم‌زمان → HTTP 409 و پیام «دوباره تلاش کنید».
